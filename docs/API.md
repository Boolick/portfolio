# API Reference

## Authentication

The API utilizes three distinct security and verification mechanisms across route handlers:

1. **Session Cookie Authentication**: Administrative routes and CMS mutations use `@supabase/ssr` server clients (`src/shared/api/supabase/server.ts`). Auth credentials (`email`, `password`) are exchanged via `POST /api/auth/login` for an HTTP-only session cookie. Mutating requests enforce CSRF origin checks using `verifyCsrfOrigin` (`src/shared/lib/csrf.ts`).
2. **Telegram HMAC-SHA256 Validation**: Telegram Mini App requests to `POST /api/telegram/visit` require raw `initData` query strings generated by Telegram. Signatures are validated using HMAC-SHA256 derived from `TELEGRAM_BOT_TOKEN` in `src/shared/lib/telegram/verify-init-data.ts`.
3. **Secret Token Header / Query Verification**:
   - Webhooks received at `POST /api/telegram/webhook` require matching header `X-Telegram-Bot-Api-Secret-Token: <TELEGRAM_WEBHOOK_SECRET>`.
   - On-demand ISR revalidations at `/api/revalidate` require `?secret=<REVALIDATE_SECRET>` query parameter matching `REVALIDATE_SECRET` or `SUPABASE_SERVICE_ROLE_KEY`.

## Endpoints Overview

| Method | Path | Description | Auth Required |
|--------|------|-------------|---------------|
| `POST` | `/api/auth/login` | Authenticates administrator with email & password, sets session cookie | CSRF Check |
| `POST` | `/api/auth/logout` | Revokes active Supabase session and clears cookie | CSRF Check |
| `GET` | `/api/auth/session` | Retrieves active user session and admin role status | None |
| `POST` | `/api/revalidate` | On-demand cache invalidation for static pages | `REVALIDATE_SECRET` |
| `GET` | `/api/revalidate` | Query-based cache invalidation alias | `REVALIDATE_SECRET` |
| `POST` | `/api/telegram/visit` | Validates Mini App initData and logs visitor telemetry | HMAC `initData` |
| `POST` | `/api/telegram/webhook` | Handles bot updates (messages, commands, inline queries) | Webhook Secret Header |
| `GET` | `/api/track-visit` | Logs referral query visit and sends alert to Telegram owner | None |
| `GET` | `/.netlify/functions/track-visit` | Netlify serverless fallback handler for referral visit tracking | None |

## Request and Response Formats

### 1. Authentication Login (`POST /api/auth/login`)

**Request Body:**
```json
{
  "email": "admin@example.com",
  "password": "strong-password-here"
}
```

**Success Response (`200 OK`):**
```json
{
  "user": {
    "id": "c8d8b6f0-1234-4567-89ab-cdef01234567",
    "email": "admin@example.com"
  }
}
```

### 2. Session Status (`GET /api/auth/session`)

**Success Response (`200 OK`):**
```json
{
  "user": {
    "id": "c8d8b6f0-1234-4567-89ab-cdef01234567",
    "email": "admin@example.com"
  },
  "isAdmin": true
}
```

### 3. Telegram Mini App Visit Event (`POST /api/telegram/visit`)

**Request Body:**
```json
{
  "initData": "query_id=...&user=...&auth_date=...&hash=...",
  "path": "/projects/high-load-fintech",
  "startParam": "ref_linkedin",
  "event": "view",
  "meta": "desktop"
}
```

Supported `event` values: `"view"`, `"download_cv"`, `"share_case"`, `"cta_click"`.

**Success Response (`200 OK`):**
```json
{
  "success": true,
  "verified": true,
  "userId": 123456789
}
```

### 4. Cache Revalidation (`POST /api/revalidate`)

**Query Parameters:**
- `secret`: Revalidation secret string matching `REVALIDATE_SECRET`.
- `path` (optional): Path to revalidate, defaults to `"/"`.

**Success Response (`200 OK`):**
```json
{
  "revalidated": true,
  "path": "/projects/fintech-architecture",
  "timestamp": "2026-11-01T19:00:00.000Z"
}
```

### 5. Referral Visit Tracking (`GET /api/track-visit`)

**Query Parameters:**
- `ref`: Referral source identifier (e.g. `github`, `linkedin`, `cv_qr`).

**Success Response (`200 OK`):**
```json
{
  "success": true,
  "ref": "linkedin",
  "sent": true
}
```

## Error Codes

API route handlers return normalized error objects:

```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "Email and password are required.",
    "status": 400
  }
}
```

Standard HTTP status codes utilized:

| Status Code | Meaning | Typical Trigger |
|-------------|---------|-----------------|
| `400` | Bad Request | Missing required parameters or malformed JSON payload. |
| `401` | Unauthorized | Invalid login credentials, invalid webhook token, or bad revalidation secret. |
| `403` | Forbidden | CSRF origin validation failure or non-admin access attempt. |
| `404` | Not Found | Requested entity or case study not located. |
| `429` | Too Many Requests | Rate limit exceeded on Telegram visit tracking or lead flood protection. |
| `500` | Internal Server Error | Unhandled server error or upstream connection breakdown. |

## Rate Limits

- **Telegram Visit Telemetry (`/api/telegram/visit`)**:
  - In-memory IP rate limiter: **20 requests per 60 seconds** window per IP.
  - Event deduplication: **10 minutes window** per unique `userId + event + path` tuple.
- **Lead Message Forwarding (`/api/telegram/webhook`)**:
  - Flood protection: Maximum **3 messages per 10 minutes** per Telegram user ID for inbound contact messages.
